**Scope:** source-only comparison of Mirror `main` at `65491c2590f530c0335dd5172d0f49cbb6884db7` and Approvals `main` at `ccbcbd8f6ef6a3d8ad0293f935cf92b16864cf30`. These are observed local and Gateway GitHub main SHAs, not installed runtime/image SHAs. No live Mirror v2 admission, signer, WRITE, deployment or Windows test is claimed. The normative stage plan remains [BACKLOG-IMPROVEMENTS](../BACKLOG-IMPROVEMENTS.md), wire contract [MIRROR_API_CONTRACT_V1](../MIRROR_API_CONTRACT_V1.md), and [READ-V2](../READ-V2.md).

## Findings and decisions before implementation

1. **ASK preflight actor provenance — BLOCKED.** Gateway `core.py:submit()` calls adapter `prepare(payload)` *before* storing the authenticated actor/request row; `integrations/mirror/read_v2.py:trusted_identity()` retrieves that row only in `execute/reconcile`. Its current assumption cannot be transplanted to ASK preparation. `ExtensionAdapter.prepare(request)` and `Context` do not carry an authenticated actor. Introduce a narrow trusted Core-to-adapter preparation context, server-created from `core.client()` authentication, that binds actor/requestId/service/operation/target without exposing identity in public params; validate the identity at execute again. Review Core submit/revalidation fingerprint and snapshot semantics before coding. Do not infer actor from an untrusted query or `approved=true`.

2. **Persisted preview identity — BLOCKED.** `machine_reads.py` has a unique `preview_id` and durable frozen data per **READ request_id**, but only `preview(repo,actor,read_uuid,generation)` and bound `lookup(repo,actor,effect_uuid)`. No closed ASK-time read-by-`previewId` API exists. P4 needs an authenticated server-internal lookup of the original persisted snapshot using exact actor/repo/previewId, with immutable origin, expiry and generation, without recomputing a preview or refreshing TTL. The ASK `executeParams` must compare `previewId/expectedHead/targetSha/configGeneration` byte-for-byte to that snapshot; stale means a **new** preview and ASK. No other actor's UUID or Browser preview may be adopted.

3. **Credential/signing separation — BLOCKED.** Gateway `extensions/model.py:Operation.credential` and `extensions/runtime.py:Context` select a **single** vault alias/secret for a given operation; existing `CredentialVault` provides generation-CAS rotation and protected files, but not an Ed25519 signer or its key ID/rotation/revocation trust profile. Design a separate execution-only signing capability and WRITE transport credential, distinct from the READ alias. Signing must be invoked only *after* Core approval, policy/credential revalidation and exact persisted preview check, never by READ/preview/lookup or a caller-chosen key. Preserve pinned HTTPS/443 and fixed Windows public-key trust, and define generation rollover, revoke-before-dispatch and rollback behavior before implementation.

4. **Atomic association/reservation — BLOCKED.** `machine_reads.py` creates `machine_bindings` but has no production writer. `pull.py:PullWorker.run()` reserves a `pull_receipts` row inside `BEGIN IMMEDIATE` before any Git, with replay returning status; this is the existing worker to extend. P4 must verify proof/identity, then insert the immutable machine association and effect reservation in **one SQLite transaction under the same ledger**, with constraints for UUID uniqueness and repo-wide unresolved writers. A separately committed binding followed by `run()` is an invalid gap. Crash after reservation means lookup only, never implicit redispatch. Browser and machine effects must continue through one writer guard and lock.

5. **Proof validation — BLOCKED.** `docs/unified-api/schemas.json` closes execute params, dispatch claims and `proof`; `MIRROR_API_CONTRACT_V1` specifies Ed25519 canonical domain-separated signing. No accepted source currently signs/verifies an actual ASK dispatch. Windows must verify signed claims (actor/repo/request UUID/preview/config generation/exact SHA/issuer/audience/keyId/fingerprint/time) against the persisted snapshot, with bounded expiry and pinned public key *before* reservation. Bearer alone cannot dispatch. A matching existing reservation is lookup-only, even after proof expiry; a new UUID requires a current, valid proof.

## Source-preserving P4 implementation sequence

1. Gateway: design and test trusted *pre-approval* actor context without weakening generic Core permission/replay checks. Add negative tests for actor spoofing and Core policy-version changes.
2. Mirror: add a private, bounded, strict persisted-preview reader by `previewId`. Test cross-actor, wrong repo, expiration, generation change, stale exact HEAD and disabled writer paths.
3. Gateway: implement reviewed separated READ / WRITE / Ed25519 signing roles using existing owner-managed vault/controller, with explicit key lifecycle and Windows pinning. Do not provision secrets in source PRs.
4. Mirror: implement verification and atomic `machine_bindings` + `pull_receipts` association/reservation using the **existing** ledger and worker. Resolve concurrent Browser/AI requests, lost ACK and crash states with no second effect.
5. Add transport/integration negatives: Reject/no approval, READ bearer on WRITE, wrong key/claim/signature/actor/repo/SHA, TTL/policy/revocation, replay/conflict, concurrent writers, crash/lost ACK/timeout, original-UUID receipt lookup and readback. Keep v1 exact and every new operation default `DENY`.
6. Only after source CI, owner-managed READ v2 TLS/identity/negative live gates, security review and a **separately approved release window**, consider admission of ASK and owner-controlled deployment. P5 release/cutover remains distinct.

## STOP conditions and remaining evidence

- **SOURCE REVIEW ONLY**: neither target repo has P4 signed dispatch/admission capability demonstrated; do not mark `execute_windows_pull_v2.implemented=true`, activate policy, grant a WRITE credential, provision keys, launch a second listener, restart/recreate services or migrate receipts.
- **LIVE UNKNOWN**: installed Windows Mirror version, Gateway image/catalog, actual CA/credential scopes and machine-generation binding have not been tested here. Source merges and Gateway GitHub repo visibility do not prove these.
- **TEST ACCEPTANCE PENDING**: negative/crash/replay tests and real Windows end-to-end verification must follow implementation. Existing offline READ fixtures are not substitute evidence of ASK or safe Git effects.
